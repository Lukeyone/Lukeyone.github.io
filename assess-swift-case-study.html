Latest implemented system

Independent development foundation

Vendor-specific runtime coupling and preview-origin assumptions were removed. Node, npm, Deno and Supabase CLI versions are pinned, with npm as the single package manager and GitHub as the canonical source.

Reproducible local data plane

A Docker-backed local Supabase environment can be rebuilt from committed migrations and visibly synthetic fixtures, including Auth users, assessments, document rows and private Storage objects.

Cross-user isolation

Two authenticated synthetic users exercise bidirectional denial checks across assessments, documents, extracted information, queue rows and private Storage operations.

Quarantine and promotion boundary

Browser uploads enter a private quarantine bucket. Server-side processing verifies ownership and path structure, detects the file family from bytes, enforces bounded PDF/PNG/JPEG structure limits, performs fail-closed malware scanning and promotes only the exact validated clean bytes.

Assessment-scoped lifecycle

Authoritative manifests, server SHA-256 identity, token-scoped promotion, no-reupload retry recovery, processing gates, two-bucket cleanup and persisted reconciliation provide a bounded upload and deletion lifecycle.

Governance controls

Legal holds and approval-gated retention cover eight asset classes. Production limits and retention values deliberately remain fail-closed until approved by the responsible owner.

The complete Docker/Supabase/ClamAV security matrix has previously reached clean migration replay, synthetic authentication, isolation, quarantine, valid-document promotion, structurally invalid document rejection, EICAR detection and scanner-outage recovery.

Engineering principle: visible known debt is safer than an empty green check. Existing business-rule mismatches remain isolated in a named non-blocking diagnostic rather than being deleted or silently redefined.

Remaining blocker

The latest full Security Gate exposed a nondeterministic repeated-cleanup/idempotency issue in the reconciliation-completion path. The next accepted candidate must validate the reconciliation result shape, require the final update to return the expected deleted row, derive idempotent state from the locked authoritative result and then pass one final deliberate full gate.
